# AI 推理成本将降千倍：从芯片到电力的全栈优化 —— Sal Research（前 NVIDIA 工程师 Neil）· ILTB Podcast · 2026-08-25

> **总览**
>
> Sal Research 创始人 Neil（前 NVIDIA 资深芯片工程师）阐述了一个核心判断：AI 的下一场革命不是模型更大，而是推理更便宜——具体来说是通过全栈优化（软件→芯片→数据中心→电力）将 token 成本降低三个数量级，达到当前价格的千分之一。他将公司定位为"token 工厂"，目标是用最低成本每 token 提供无限供给，服务对象是长时运行的后台代理（background agents），而非实时聊天机器人。
>
> 最具反直觉冲击的细节是：GPU 上延迟与吞吐存在不可调和的根本性矛盾——你无法同时优化两者。这意味着 NVIDIA 为低延迟设计的 NVLink 互联技术在后台代理场景下价值有限，而 AMD 等"次优"芯片因无需高速互联反而成为高性价比选择。Neil 的公司有意购买全球任何芯片、任何地点、任何时段的算力，包括被大厂忽视的边缘产能和间歇性可再生能源驱动的小型数据中心。
>
> 本集最可迁移的框架是"栖息者策略"（scavenger strategy）：不与 Anthropic/OpenAI 争夺集中算力供应，而是通过收购被主流忽视的碎片化芯片和分散电力，积累成规模化的聚合工厂——如同钢铁行业的小型电弧炉颠覆大型一体化钢厂。这一思路对所有资源受限但希望在巨头夹缝中找到供给侧套利机会的创业公司都有参考价值。

## TL;DR

1. **AI 推理将从实时聊天转向后台长时间运行代理**：模型运行数小时而非等待人类即时反馈，token 消耗量将从实时 10:90 比例反转至后台 90%。
2. **GPU 延迟-吞吐矛盾是不可调和的物理限制**：批处理提升吞吐但增加单 token 延迟，这是所有计算系统的根本权衡，不可能同时达到两者最优。
3. **非 NVIDIA 芯片被严重低估**：AMD 等芯片无需高速互联（NVLink），在吞吐优先场景下是"每浮点美元"最优选择，市场对它们的低估恰恰是套利空间。
4. **数据中心将走向分布式小型化**：1 兆瓦级分布式数据中心可容忍 95% 正常运行时间，远低于传统数据中心的"五个九"要求，大幅降低基建成本。
5. **HBM 内存是当前最严重的供应链瓶颈**：相比 TSMC 产能和芯片设计，HBM 的供应短缺最有可能持续且最难以绕过，将推高所有消费电子价格。

## 核心论点（金字塔：结论 → 论据 → 理解）

### 论点 1：AI 推理的未来是长时间后台运行的自主代理，而非实时聊天

- 论据：Opus 4.5 首次证明代理可以持续运行约一小时；当前模型已可运行数小时。行业数据显示背景与实时工作负载正趋近 50:50，年底预计达 90:10（后台为主）。
- 理解：人类的注意力才是瓶颈——你不会每 5 分钟管理一次同事，而是给高层任务后一周才检查一次。智能代理应遵循同样的"人类时间尺度"交互模式。这将解锁深度研究（10000+来源的信息索引）、网络安全（全量代码渗透测试）等需要巨量 token 但人类无法逐秒监督的场景。

### 论点 2：GPU 吞吐与延迟存在不可调和的物理矛盾，后台代理应选择吞吐优先

- 论据：GPU 在大批次并行运算时效率最高（可达峰值 70-80%），但大批次意味着每个 token 的等待时间增加（类比公交车与私家车）。当前所有推理服务商都为聊天机器人优化了延迟，牺牲了吞吐。
- 理解：后台代理不需要"秒回"——它可以在用户睡觉时完成工作。将 GPU 从延迟优化切换到吞吐优化，可以显著提升单芯片每小时 token 产量，这就是 Sal Research 的核心软件优势。

### 论点 3：NVIDIA 的 NVLink 技术在后台推理场景下价值有限，非 NVIDIA 芯片反而成为套利机会

- 论据：NVLink 实现 GPU 间高速互联，是低延迟推理的"必选"技术，但采用张量并行的扩展是亚线性的（8 块 GPU 仅 4-5 倍加速）。吞吐优先场景可用专家并行或流水线并行替代，不依赖高速互联。AMD 芯片在"每浮点美元"指标上优于 NVIDIA。
- 理解：当取消了"必须高速互联"这一约束后，芯片选择从"唯一 NVIDIA"变为"任何在基础算力上足够好的芯片"，这使 Sal Research 可以在全球任何地方采购任何芯片——包括被大厂忽视的二手或边缘产能。

### 论点 4：分布式小型数据中心是推理时代的新基建范式

- 论据：训练集群需要集中式超大规模数据中心（100+ 兆瓦），但推理可分布在 1 兆瓦级的小型数据中心（约 8 个冰箱大小的机架）。这类设施可容忍 95% 正常运行时间（传统数据中心要求 99.999%），无需冗余网络和柴油发电机。
- 理解：95% 正常运行时间意味着每年有约 18 天宕机，对传统服务不可接受，但对后台代理是线性成本——工作负载自动迁移到其他数据中心即可。这使得大量原本"不可用"的分布式电力（如间歇性太阳能/风电）首次变得可用。

### 论点 5：当前 AI 基础设施最严重的低效是注意力机制的 KV 缓存压缩不足与全球算力的闲置浪费

- 论据：KV 缓存中每 token 存储数千字节数据，可能高出实际需要 1-2 个数量级；NVIDIA 今年出货约 500 万颗 Blackwell 芯片，大量闲置在私人机房中未被充分利用。DeepSeek 在 KV 缓存压缩方面每年取得数量级进展。
- 理解：KV 缓存是"对话的动态记忆"，随对话长度线性增长且常超过模型权重大小。Transformer 的"原罪"是将本质内存密集的注意力层与计算密集的 MLP 层放在同一芯片上——这是 Cerebras/Grock 等专用芯片的市场切入点。

## 关键细节

- **公司定位**：Sal Research 是一家"token 工厂"，提供开源大模型推理 API 和长时运行代理沙箱（可运行数小时/数天/数周），目标是行业最低的每 token 成本。公司信条是"abundance"（丰富）。
- **NVIDIA 文化细节**：NVIDIA 以极端节俭著称——2015-2016 年期间连冰箱里的牛奶都需要每月凑 1 美元加入"牛奶俱乐部"才能使用；公司追求"光速"（speed of light）工程哲学，即达到硬件物理极限性能。
- **Cerebras/Grock 的 SRAM 路线**：Cerebras 使用整片晶圆（而非单个 800mm² 芯片），通过划片线互联获得约 50GB 片上 SRAM，带宽达 21 PB/s（对比 NVIDIA Blackwell HBM 约 10 TB/s），可将万亿参数模型在毫秒内加载——适合权重读取，但无法解决 KV 缓存的容量需求。
- **"蒸馏是盗窃"的反驳**：开源模型可训练于 AI 生成的代码（GitHub 上大量由 Cloud Code 等工具生成），构成"隐性蒸馏"——用户拥有 AI 输出并选择公开分享，从技术上无法阻止模型能力的扩散。
- **百万 token 价格锚点**：以 OpenAI 定价，1 万亿 token 约 500 万美元；Sal Research 目标是将此降至数万美元，实现三个数量级的成本下降。
- **芯片供应链四大瓶颈**：TSMC 晶圆产能、HBM 内存产能、先进封装产能、电力供应——任何新芯片创业公司必须对这四者有清晰的应对方案。
- **"没有坏芯片，只有差定价"**：Neil 认为任何芯片都有比较优势（computational advantage），关键是找到该优势并将其嵌入异构推理系统中——TPU、Trainium 等"非主流"芯片均可被纳入。

## Key Takeaways（核心精华）

- **"最佳延迟就是零延迟"**：后台代理的根本逻辑是用户不应在等待中——工作应在无人监督时完成，这从根本上颠覆了"越快越好"的推理优化方向。
- **GPU 延迟-吞吐矛盾是物理定律级限制**：不是技术不够好，而是任何计算系统都必须在"窄而快"和"宽而慢"之间选择——后台代理选择了后者。
- **非 NVIDIA 芯片的机会来自约束解除**：当吞吐优先取代延迟优先，NVLink 不再是必需品，AMD/TPU 等芯片的"每浮点美元"优势立即显现。
- **95% 正常运行时间对后台代理是"够用"的**：线性成本模型（95% vs 99% 仅线性差异）加上自动工作负载迁移，使分布式小型数据中心首次具有经济可行性。
- **HBM 供应是最难绕过的瓶颈**：相比芯片设计、封装和电力，HBM 内存的产能扩张最慢且受周期性约束（博伊西的美光们多次被周期伤害），推高所有消费电子价格。
- **开源模型能力扩散不可阻挡**：即使前沿实验室领先 3-6 个月，AI 生成内容的公开（如 GitHub 代码）构成隐性蒸馏，模型能力扩散是物理必然而非政策问题。

- **与常见认知的差异**：
  - 市场普遍认为 NVIDIA 是推理场景的绝对赢家——Neil 认为在吞吐优先的后台代理场景下，NVIDIA 的核心竞争优势（NVLink 互联）变得无关紧要。
  - 市场将间歇性可再生能源视为数据中心禁区——Neil 认为后台代理可容忍数天甚至数周的电力中断，使此前"不可用"的分布式风光电力首次变得有价值。
  - 投资者担忧半导体在 S&P 500 中 19-21% 的权重类似 2000 年网络泡沫——Neil 指出关键区别是当前 token 消耗是即时价值验证（非投机性），与光纤时代"预期未兑现的需求"有本质差异。

  - 95% 正常运行时间的分布式数据中心在实际部署中的可靠性是否确实线性可接受？
  - 后台代理的工作负载增长是否会如预期达到 token 消耗量的 90%？
