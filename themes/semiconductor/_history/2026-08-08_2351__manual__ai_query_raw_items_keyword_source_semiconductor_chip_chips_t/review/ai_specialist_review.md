## ⚠️ concern

- **训练与推理需求已区分，方向正确，但还不够量化。** 稿件明确指出训练更重视通用性、软件生态和快速迭代，推理更重视单位成本和能效，这一拆分符合 AI 需求侧分析要求。但目前没有给出训练/推理在云算力、芯片采购、收入或利用率中的实际占比，也没有区分 prefill、decode、长上下文、实时低延迟推理等不同推理负载。建议至少把“推理增长”拆为模型规模、请求量、上下文长度、batch size、延迟要求和每 token 成本等可观测变量。

- **GPU 与 ASIC 竞争框架基本完整，但 Marvell/博通的角色仍偏名录化。** 稿件已指出 ASIC 主要先替代稳定、规模化的推理工作负载，也已列出 Marvell、博通作为定制 ASIC/交换芯片公司；但没有说明定制 ASIC 收入是否来自 XPU、网络芯片、光互连配套还是其他业务，也没有客户、项目、量产时间、订单规模或 ASP 数据。建议将“定制 ASIC 设计服务/平台芯片”和“交换芯片”分开，避免把博通、Marvell 的所有 AI 相关收入都等同于 GPU 替代需求。

- **光互连已纳入，但需求验证仍停留在产品链条层面。** 稿件明确纳入 Lumentum、Coherent、中际旭创、新易盛、天孚通信、Fabrinet、Astera Labs、Credo 等，并区分光芯片、光模块、DSP、重定时器和交换芯片，这是合格的产业链拆分。但尚未提供 800G/1.6T 出货、客户集中度、订单、ASP、库存、应收账款或云厂商项目进度数据。不能仅凭“训练转推理仍需要网络”推出光互连景气扩张，建议改成“需求机制成立，但订单兑现未验证”。

- **推理成本和单位经济性虽被提及，但没有形成需求持续性的判断规则。** 稿件提到“每单位推理成本、能效、总拥有成本、每次推理成本”，但没有明确何种成本下降会刺激需求、何种成本下降会反而减少芯片采购。例如单位 token 成本下降可能带来使用量弹性和总算力需求增长，也可能在请求量不变时降低云厂商收入与资本回报。应补充：推理需求持续的必要条件是请求量/收入增长足以超过单位成本下降和折旧、电力、网络成本；否则“效率提升”可能意味着更少的 GPU 采购，而非更多的总需求。

- **“GPU 总需求未必下降”表述合理，但缺少反向渠道。** 稿件主要强调 ASIC 稀释 GPU 边际份额，同时保留 GPU 总需求增长可能性；应进一步说明三种可能：总推理量增长快于 ASIC 替代，GPU 与 ASIC 共振增长；推理效率提升导致单位算力需求下降，GPU 总量增速放缓；自研 ASIC 规模化后挤压 GPU 采购。当前稿对第三种和第二种情景描述不足。

- **HBM 配置下降的逻辑已识别，但相关报道的证据等级需要进一步降级。** 稿件已指出 Rubin Ultra 可能下调 HBM 配置，并讨论其对单颗加速器价值量、性能和交付节奏的影响，这是重要需求侧风险。不过该事件来自新闻/供应链报道，尚非正式产品规格或公司公告，建议明确写为“未经 NVIDIA 正式确认的报道”，不能作为 HBM 需求拐点事实。

- **市场定价部分仍使用了缺少当前来源的历史数据边界。** 当前 session 稿已避免写入具体 PE 和目标价，但主题已有旧版本记录过 NVDA、TSMC 等财务和估值数字。应确认定稿不引用这些无法在本轮复核的历史接口结果，也不要把当前股价上涨解释为 AI 需求验证。价格变化只能说明市场交易状态，不等于订单、收入或 ROI 已确认。

- **稿件对公司最新新闻的覆盖不均衡。** AMD 的 Taalas 收购已被覆盖，并且正确指出“收购不能证明大规模 ASIC 订单”；但 NVIDIA 的近期产品、软件和生态事件几乎没有纳入需求侧判断。NVIDIA 与 SSI 的长期合作、Vera/Alpamayo 等事件可能强化其平台生态和推理/物理 AI路线，应至少作为竞争格局观察项，而不是遗漏。
