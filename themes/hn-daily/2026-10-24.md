### 4. Dijkstra 1978 年旧文《论"自然语言编程"的愚蠢》重登 HN

| 原文 | [The foolishness of "natural language programming" (1978)](https://www.cs.utexas.edu/~EWD/transcriptions/EWD06xx/EWD667.html) |
| 热度 | ▲ 298 · 💬 196 · 作者 xiaoyu2006 · 2026-10-23 00:52 UTC |
| --- | --- |
| 摘要 | Dijkstra 手稿 EWD667：把"用母语指挥机器"的诉求拆解为接口理论问题——接口选择不是固定工作量的分配，因为跨接口协作与沟通本身的开销会增加；改用自然语言接口可能让两侧的工作量同时上升（他引 Housman："一瞬间很长，思考很痛苦"）。他主张"窄接口"优于"宽接口"，并预言自然语言界面会把机器搞得更复杂、把人变得更懒于精确思考。 |
| 批注 | 48 年后重登热榜本身就是答案：LLM 把"自然语言编程"从假设变成现货，而 Dijkstra 的核心论点（接口带宽增加会同时加重两侧负担、形式符号的价值恰在其强制精确性）依然是对 vibe coding 最锋利的哲学反驳——评论区 196 条的争论强度说明这条张力在 2026 年不减反增。 |

**kevin_kelly 视角：** Dijkstra 论证的是接口带宽的守恒代价，而 LLM 改变的恰恰是"精确表达"的生产成本——当机器第一次能廉价地把模糊意图翻译成形式规格，宽接口的惩罚项被大幅压低，他 1978 年的成本算盘不再成立；但他的深层警告仍然有效：精确性不只是成本，也是强制思考的纪律，vibe coding 丢掉的可能是"被迫想清楚"这个副产品。判断：自然语言编程作为界面层是必然（12 趋势中的"知化＋互动"），Dijkstra 描述的是它必须配套付出的验证成本——这笔账不会消失，只会转移给测试、类型与形式化验证工具（呼应本周 Anthropic 形式化验证研究的热度）。

**ai_specialist 视角：** 技术层面看，Dijkstra 的"窄接口"预言其实已在 LLM 编程范式内部部分兑现：生产级 agent 框架没有让模型用自由自然语言驱动一切，而是收敛到结构化 tool-call 与类型化 API——自然语言只做意图入口，形式规格由接口层强制。真正的瓶颈从来不是"生成"而是"验证"：LLM 已能把模糊意图廉价翻译成代码，但判断代码是否符合意图仍需测试、类型与证明——这正是 Anthropic 形式化验证研究当周登上热榜的技术背景。vibe coding 的真实风险不是"人变懒"，而是验证成本被系统性低估后欠账累积。
